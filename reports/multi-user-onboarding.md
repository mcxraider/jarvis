# Jarvis Multi-User Onboarding

Jarvis resolves users, preferences, and connected services from Supabase. Use
the administrative CLI for every onboarding or integration change; do not edit
rows manually or add credentials to environment maps.

## Prerequisites

Use a dedicated Postgres login that inherits `jarvis_admin_runtime`:

```bash
export JARVIS_ADMIN_POSTGRES_DSN='postgresql://...'
```

Keep this DSN only in a protected admin environment. Never deploy it with the
Telegram or Python runtime. The CLI never falls back to
`JARVIS_POSTGRES_DSN`.

Run commands from the repository root:

```bash
venv/bin/python scripts/manage_integrations.py --help
```

Add `--json` before the command group for sanitized machine-readable output.
State-changing commands accept `--actor`; its default is `admin:cli`.

## Information to Collect

Ask the user for:

- Telegram numeric user ID and username.
- Preferred display name, IANA timezone, and locale.
- Structured assistant preferences.
- A Todoist API token, when Todoist is requested.
- Google authorized-user JSON generated by `scripts/generate_friend_token.py`,
  when Calendar is requested.

Transfer credentials through a secure channel. Never paste them into a command
argument, chat log, `.env`, or source-controlled file.

Supported preference values are:

| Preference | Values |
|---|---|
| Tone | `casual`, `neutral`, `professional` |
| Verbosity | `concise`, `balanced`, `detailed` |
| Task provider | `todoist`, `google_calendar` |
| Event provider | `todoist`, `google_calendar` |
| Calendar usage | `default`, `explicit_only` |

Use `explicit_only` when Calendar should be callable but should not receive
event-like requests unless the user names it.

## Onboard a User

### 1. Create the user and primary Telegram identity

```bash
venv/bin/python scripts/manage_integrations.py user create \
  --telegram-user-id 123456789 \
  --username friend_username \
  --display-name "Friend Name" \
  --timezone Asia/Singapore \
  --locale en \
  --actor admin:onboarding
```

This atomically creates the canonical user, attaches a verified primary
Telegram identity, and records an audit event. Repeating it for the same
identity updates matching profile fields without creating a duplicate. An
identity already owned by another user fails closed.

Attach another Telegram identity to the same canonical user with:

```bash
venv/bin/python scripts/manage_integrations.py identity attach-telegram \
  --owner-telegram-user-id 123456789 \
  --telegram-user-id 987654321 \
  --username second_username \
  --display-name "Friend Name" \
  --actor admin:onboarding
```

Add `--primary` only when the new identity should replace the current primary
Telegram identity.

### 2. Set validated preferences

Create a temporary `preferences.json`:

```json
{
  "communication": {
    "tone": "casual",
    "verbosity": "concise"
  },
  "routing": {
    "task_provider": "todoist",
    "event_provider": "google_calendar",
    "calendar_usage": "default"
  },
  "domains": {
    "todoist": {},
    "google_calendar": {
      "event_category_defaults": {
        "social": "Personal",
        "work": "Work",
        "classes": "NUS Schedule"
      }
    }
  }
}
```

Validate and store it:

```bash
venv/bin/python scripts/manage_integrations.py preferences set \
  --telegram-user-id 123456789 \
  --file preferences.json \
  --actor admin:onboarding
```

Use `--file -` to read JSON from stdin. Unknown fields, unsupported values, and
invalid schemas are rejected before any database change. Updates increment the
preference revision.

### 3. Import Todoist

Put the token in a mode-`600` temporary file, or pipe it over stdin:

```bash
chmod 600 /tmp/friend.todoist-token
venv/bin/python scripts/manage_integrations.py credential import \
  --telegram-user-id 123456789 \
  --provider todoist \
  --secret-file /tmp/friend.todoist-token \
  --account-label "Friend Todoist" \
  --actor admin:onboarding
rm /tmp/friend.todoist-token
```

Stdin form:

```bash
security find-generic-password -w -s friend-todoist |
  venv/bin/python scripts/manage_integrations.py credential import \
    --telegram-user-id 123456789 \
    --provider todoist \
    --secret-file - \
    --account-label "Friend Todoist"
```

The CLI performs a harmless authenticated Todoist read before atomically
creating or updating the Vault secret and connection.

### 4. Import Google Calendar

The user runs the OAuth helper and securely returns its authorized-user JSON.
Import it directly from the temporary file:

```bash
chmod 600 /tmp/friend-calendar.json
venv/bin/python scripts/manage_integrations.py credential import \
  --telegram-user-id 123456789 \
  --provider google_calendar \
  --secret-file /tmp/friend-calendar.json \
  --account-label "Friend Google Calendar" \
  --actor admin:onboarding
rm /tmp/friend-calendar.json
```

The CLI parses and refreshes the credential, lists calendars to validate live
access, and stores only the encrypted credential plus sanitized account
metadata. Runtime token refreshes are written back to Vault.

### 5. Verify capabilities and integrity

```bash
venv/bin/python scripts/manage_integrations.py capabilities show \
  --telegram-user-id 123456789

venv/bin/python scripts/manage_integrations.py audit check
```

`capabilities show` reports only user/profile identifiers, preference revision,
connection state, account label, validation time, and active capability names.
It never returns preferences or credential material.

`audit check` exits `0` when clean and `2` when it finds:

- Jarvis Vault secrets with no connection.
- Connections whose referenced Vault secret is missing.
- Users without a verified Telegram identity, valid preferences, or complete
  required profile fields.
- Invalid routing preferences.
- A configured task/event provider that is not connected and enabled.

After these checks, ask the user to perform one read and one create against each
connected provider, plus a request that exercises their configured routing.

## Credential Lifecycle

Validate the currently stored credential without printing it:

```bash
venv/bin/python scripts/manage_integrations.py credential validate \
  --telegram-user-id 123456789 \
  --provider todoist \
  --actor admin:maintenance
```

Rotate a healthy connection with new credential material:

```bash
venv/bin/python scripts/manage_integrations.py credential rotate \
  --telegram-user-id 123456789 \
  --provider todoist \
  --secret-file - \
  --actor admin:maintenance
```

Temporarily disable a provider while retaining its connected status and Vault
secret:

```bash
venv/bin/python scripts/manage_integrations.py credential disable \
  --telegram-user-id 123456789 \
  --provider todoist \
  --actor admin:maintenance
```

Reconnect a disabled, disconnected, `needs_reauth`, or revoked connection with
replacement credentials:

```bash
venv/bin/python scripts/manage_integrations.py credential reconnect \
  --telegram-user-id 123456789 \
  --provider todoist \
  --secret-file - \
  --actor admin:maintenance
```

Logically revoke a connection:

```bash
venv/bin/python scripts/manage_integrations.py credential revoke \
  --telegram-user-id 123456789 \
  --provider todoist \
  --actor admin:security
```

Revocation sets the connection to `revoked` and disabled. The encrypted Vault
secret remains referenced for controlled recovery, but runtime resolution
cannot use it. This command does not revoke the token at the upstream provider.
Use `reconnect` with replacement credentials to restore access.

Disable all runtime access for a user:

```bash
venv/bin/python scripts/manage_integrations.py user disable \
  --telegram-user-id 123456789 \
  --actor admin:security
```

Every mutation records a sanitized audit event. Capability and integrity reads
do not create audit rows.

## Exit Codes and Secret Safety

| Exit | Meaning |
|---:|---|
| `0` | Command succeeded; integrity scan is clean |
| `1` | Validation, conflict, provider, or database operation failed |
| `2` | Integrity scan completed and found issues |

Credential content is accepted only through `--secret-file PATH` or
`--secret-file -`. It is never accepted as an argument, printed in human or
JSON output, stored in audit details, or included in CLI error messages.

## Runtime Flow

```text
Telegram update
  → verified user_identities row resolves the active canonical user
  → versioned user_preferences are validated
  → integration_connections intersect with registered domain adapters
  → Vault secrets resolve only for connected and enabled domains
  → one secret-free capability snapshot drives tools, prompts, state, and traces
```

Changes apply to new requests immediately. Interrupted threads retain their
original saved snapshot until resumed or abandoned.

Do not restore environment token maps, per-user token files, runtime
auto-provisioning, hard-coded profiles, or generic Vault permissions on the
application role.
